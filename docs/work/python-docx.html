Developers creating and modifying Word documents with python-docx-ng.
The job
Find a style by its valid name or ID, including text that contains quotation marks.
Why it helps
Preserves valid names instead of asking users to rename styles to work around a lookup error.

python-docx-ng · PR #131

Merged 4 August 2026

Correction & regression tests

Original issue & diagnosis ↗

A normal name exposed a lookup problem.

A style could be created with a valid name containing quotation marks, yet fail when retrieved. The lookup placed the name directly inside an XPath expression, where its quotation marks could change the expression’s meaning.

Pass the text separately from the expression.

The contribution uses bound XPath variables across style-name, style-ID and latent-style lookup paths, while retaining namespace handling. Regression cases cover the shared wrapper and the public style API.

The upstream issue supplied the diagnosis. I used AI to implement the correction and add regression cases. The maintainer checked mixed quotes, save/load and namespace behavior, then merged the change.

Evidence and contribution scope

The public pull request contains the discussion, changed files and maintainer response. It records the original diagnosis, the correction, regression coverage and acceptance of the change upstream.
